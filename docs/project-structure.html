3核心文件与功能说明

文件类型功能说明对应 CLI 子命令
cli.py 入口 命令行总入口（779 行）。用 argparse 注册全部子命令，main() 中解析参数后按 args.command 分发到对应模块的 handler。 全部命令
computer_info.py 核心 采集计算机信息：CPU（py-cpuinfo）、内存/磁盘/网络（psutil）、GPU（nvidia-ml-py），以 PrettyTable 表格输出摘要或详情。 zxtool ci
config_manager.py 核心 生成并管理 ~/.config/zxtool.toml 全局配置，涵盖 MkDocs 项目、Git 用户、Let's Encrypt、Nginx 站点、日志等配置段；支持交互式初始化。 zxtool config init / show
git_config.py 核心 检查/填充 Git 仓库 .git/config 中的 user.name / user.email；支持从配置批量 pull、clone 项目。 zxtool git config / pull
backup_manager.py 核心 目录备份复制：带时间戳的增量备份目录（.zxtool_backups）与备份记录（backup-records.md），支持 git-aware 行为。 zxtool backup copy
letsencrypt.py 核心 封装 acme.sh 实现 ACME v2 证书管理（1245 行，最大模块）：安装 acme.sh、HTTP-01/DNS 泛域名签发、自动续签、批量签发、定时任务。 zxtool le issue/renew/batch/status/revoke/cron
ssl_cert.py 核心 自签证书生成器：生成 20 年有效期 Root CA，为单域名/泛域名签发 2 年有效期证书，用于开发环境 HTTPS 调试。 zxtool ssl init/root/cert
nginx_manager.py 核心 检查本机 Nginx 可用性；根据 zxtool.toml 项目配置生成站点配置文件，支持 enable / disable / reload。 zxtool nginx check/generate/enable/disable/reload
mkdocs_manager.py 核心 MkDocs 项目管理：创建新项目脚手架、构建单个项目、基于 TOML 配置批量构建多个项目。 zxtool mkdocs create/build/batch/serve
mkpdf_manager.py 核心 Markdown 转 PDF：Markdown 渲染 + 内置 Mermaid 离线运行时 + Edge/Chrome/Chromium 无头打印；支持单文件或目录合并转换。 zxtool mkpdf
epub_manager.py 核心 EPUB 电子书转 Markdown 目录（基于 epublib），保留章节结构与内嵌图片。 zxtool epub convert
video_download.py 核心 基于 yt-dlp 的在线视频下载，带进度显示；针对 Cloudflare 反爬自动降级为 curl-cffi 浏览器模拟重试。 zxtool video
http_server.py 核心 静态文件 HTTP 服务与本地 MP4 在线播放器（使用内置 xgplayer 资源），便于局域网预览。 zxtool http serve / video
image_manager.py 核心 图片处理工具：resize（改尺寸）与 compress（压体积），支持 JPEG / PNG / WebP，基于 Pillow。 库调用
pyopt_2fa.py 辅助 解析 TOTP 密钥生成当前 2FA 验证码（pyotp），仅 16 行的小工具。 zxtool totp
logging_manager.py 辅助 统一日志初始化：格式、轮转（保留 7 份），供所有模块共用。 内部支撑
assets/ 资源 内置前端资源：mermaid.min.js（mkpdf 离线图表渲染）、xgplayer 播放器、player.css/js（http video 功能）。 被 mkpdf / http 使用
test/ 测试 pytest 单元测试，与每个功能模块一一对应（test_cli、test_computer_info……共 17 个测试文件）。 —

4运行过程

①

环境准备与安装依赖

uv 读取 .python-version 确定 Python 3.13，依据 pyproject.toml + uv.lock 创建虚拟环境并安装精确版本的依赖。

# 方式 A：全局安装为独立工具（推荐日常使用）
uv tool install zxtoolbox

# 方式 B：开发模式，在本项目内同步依赖到 .venv
uv sync
②

命令启动，进入 CLI 入口

pyproject.toml 中 [project.scripts] 定义了 zxtool = "zxtoolbox.cli:main"。执行 zxtool <子命令> 时，控制权交给 cli.py 的 main() 函数。

③

初始化日志 + 构建参数解析器

main() 先调用 logging_manager.setup_logging() 初始化统一日志，然后 build_parser() 用 argparse 注册所有子命令（ci / totp / video / http / ssl / mkdocs / nginx / config / git / epub / backup / mkpdf / le）。

④

解析并分发到功能模块

按 args.command 逐个 if 分支分发到对应模块的 handler（如 handle_ssl、handle_mkdocs），handler 再调用各功能模块（ssl_cert / mkdocs_manager 等）完成实际工作并输出结果。

# 常用命令示例
zxtool ci # 查看计算机信息（--all 查看详情）
zxtool mkpdf ./README.md # Markdown 转 PDF
zxtool ssl root # 生成根 CA
zxtool le issue -d example.com # 申请证书
zxtool git pull # 批量拉取配置的项目
zxtool http serve ./dist # 起静态文件服务
⑤

运行测试（开发场景）

pytest 从 src/zxtoolbox/test/ 收集测试，各模块的测试文件独立可运行，也可以加覆盖率统计。

# 运行全部测试
uv run pytest src/zxtoolbox/test/ -v

# 运行单个文件 / 指定用例
uv run pytest src/zxtoolbox/test/test_cli.py -v
uv run pytest src/zxtoolbox/test/test_cli.py::TestCliGit::test_git_config_check -v

# 覆盖率
uv run pytest src/zxtoolbox/test/ --cov=zxtoolbox --cov-report=term-missing
⑥

构建与发布（维护场景）

uv_build 后端负责打包构建；项目还包含基于 MkDocs 的文档站，可用 mkdocs 命令本地预览或部署。

uv build # 构建 wheel / sdist 到 dist/
uv run mkdocs serve # 本地预览文档站
uv run mkdocs build # 构建文档站到 site/
💡 说明：zxtool 若通过 uv tool install 安装，命令全局可用；若采用开发模式（uv sync），则用 uv run zxtool … 在项目虚拟环境中执行。
